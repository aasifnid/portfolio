Design System

The tokens, components and patterns behind my portfolio. Every screen is built from the same parts.

Six principles hold it together: clarity over cleverness, few choices, used well, defined once, plain words, colour used sparingly, and it works for everyone.

Buttons

Two levels. Primary is a solid ink button for the one main action, and turns accent on hover. Secondary is an outline that fills with a soft gradient. Both use the 12px small radius. A round icon button handles single-glyph actions like the recommendation arrows.

Icon · default

When to use

  • One primary button per view, for the main action.
  • Secondary for supporting actions next to it.
  • Keep labels to a verb and noun, like "View case study."

When not to use

  • Do not place two primary buttons side by side.
  • Do not use a button for plain navigation. Use a text link.
  • Do not write long labels or full sentences.

Text links

A quiet link with an optional icon and an underline that appears on hover. Used for hero and contact actions where a button would be too heavy.

See my workDefault
See my workHover
Download resumeWith icon

When to use

  • For navigation and low-weight actions.
  • Pair with a small leading icon when it adds meaning.
  • Keep the label to a few words.

When not to use

  • Do not use where a real button action is expected.
  • Do not crowd many links in a tight row.
  • Do not rely on colour alone. Keep the underline on hover.

Icons

One line-icon set across the site. Drawn on a 24px grid with a ~1.8 stroke, round caps and no fill. Used inside links, buttons, the nav and the chat.

When not to use

  • Do not mix filled and outline styles.
  • Do not use an icon alone for a critical action.
  • Do not set odd stroke weights.

Zone pills

Small colour-coded pills for data and status. Each pairs a tint with a word, so colour is never the only signal. Charts and tables only, never brand UI.

On track--data-green
Neutral--data-blue
Needs work--data-yellow
At risk--data-red

When to use

  • Inside tables and charts to mark a zone or status.
  • Always pair the colour with a readable word.
  • Keep to the four data colours.

When not to use

  • Do not use for brand or navigation UI.
  • Do not rely on colour with no label.
  • Do not invent colours outside the data set.

Work card

The full-width case-study card on the home page. A cover image, a gradient type label, the title and one line. The whole card lifts on hover.

Behavioural design
Feel Check

A student-led emotional check-in built into the start of every live class.

When to use

  • One card per case study on the home page.
  • Lead the meta with the problem type in gradient.
  • Keep the description to one line.

When not to use

  • Do not crowd the card with extra stats.
  • Do not use more than one gradient element.
  • Do not change the corner radius per card.

Project card

A smaller card for NID projects and the AI Playground. A square-ish image, a title with an optional icon, and a short line. Sits in a grid of three.

When to use

  • In a grid of three for lighter work.
  • Keep the description to one or two lines.
  • Use for side projects and playground pieces.

When not to use

  • Do not mix it with the full work card in one row.
  • Do not use for primary case studies.
  • Do not overload the title.

Recommendation

Peer recommendations. A row of selectable people, a large gradient quote mark, the quote, and prev and next controls. Click a person or use the arrows.

When to use

  • Real quotes with a name, role and photo.
  • Let people pick who they read.
  • Keep one quote in view at a time.

When not to use

  • Do not invent or reword quotes.
  • Do not stack all quotes at once.
  • Do not drop the name or role.

When to use

  • Mark exactly one as chosen.

When not to use

  • Do not mark more than one chosen.
  • Do not hide the rejected options.
  • Do not write long paragraphs in a card.

Navigation bar

The sticky bar on every page. Wordmark on the left, section links on the right. Links have no selected state. They scroll to a section and lighten to full ink on hover.

Aasif Anwar

When to use

  • Keep the same links on every page.
  • Let links hover to full ink.
  • Scroll to the section and keep the URL clean.

When not to use

  • Do not add a persistent selected state. This is a one-page scroll.
  • Do not use more than one row of links.
  • Do not put the case-study nav on the home page.
