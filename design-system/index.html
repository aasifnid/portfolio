Principles

Why before what

Six rules sit behind every choice below. When two options both look fine, the rule decides.

01

Clarity over cleverness

If a simple option and a clever one both work, pick the simple one. The main action is the most visible thing on a page. A label always beats an icon on its own.

02

Few choices, used well

Seven type sizes, one 8-point grid, even numbers, one accent. A small set of choices is what makes five pages feel like one site.

03

Defined once

Every color, size, and shared part is set in one place, so every page stays in step. Nothing is copied by hand.

04

Plain words

The writing is part of the design. No jargon, no acronyms a reader has to decode. Clear beats short.

05

Color, used sparingly

One gradient, saved for a single highlight per screen, never as a background. The solid accent is only for places a gradient cannot go, like icons and small text. Numbers are always the gradient.

06

Works for everyone

Every clickable thing has a clear focus state. Every animation can be turned off. Text stays readable on its background.

✓Do
  • Use neutrals for most of a page.
  • Use the gradient for one highlight per screen, and for numbers.
  • Use the solid accent only for icons, links, and small colored text.

✕Don't

  • Add a new color. Map a missing shade to the closest token.
  • Mix data colors into the brand UI.

Contrast: ink and ink-2 pass for body text on the light backgrounds. The lightest grey (ink-3) is only for labels and captions. Color is never the only signal: zone pills always carry a text label too.

Responsive & mobile

One layout, a few breaks

One layout that adapts at a few widths. The phone view is not an afterthought. Some parts change shape on purpose, and the navigation changes the most.

Breakpoints
720px and belowNavigation switches from a row of links to a hamburger. The menu opens as a full-width panel.
640px and belowThe main phone break. Page gutters go from 40 to 24. Section spacing tightens (home 104 to 72, case study 80 to 56). Most multi-column grids drop to one column.
480 to 560pxSmall-phone tuning. The last two-column grids (work cards, stats) stack, and the hero portrait and big numbers step down a size.
820px (hero only)The two-column hero, text beside the caricature, stacks into one column and the portrait shrinks.
What changes on a phone
  • Navigation becomes a hamburger. Tapping it slides down a full-width frosted menu with large links. Shown as Mobile menu under Organisms.
  • Every multi-column grid drops to a single column: project cards, work cards, stat tiles, image grids and pairs, decision options, the cover meta strip, and the timeline.
  • The hero stacks text above a smaller portrait, and the headline drops its hand-set line breaks so it wraps to fill each line.
  • Type scales down smoothly and never drops below a readable size.
  • Gutters and spacing tighten so the page does not feel cramped on a narrow screen.
Touch
Built for fingers, not just a mouse: hover-only touches like the custom cursor, the card lift, and the portrait reveal are switched off on touch screens, so nothing needs hover to work. The page also avoids any sideways scroll on small widths.

Built in code

How it ships

This portfolio and its design system were designed and built directly in code, then shipped to production. An AI coding assistant helped with the build. The design calls and the quality checks are mine.

01

Write the spec

Describe the part in plain words: the rule, the size, the states.

02

Build it

Turn the spec into real HTML and CSS against these tokens.

03

Review

Check it in the browser on desktop and a narrow phone, then fix.

04

Ship

Send it through a pull request; it deploys to the live site.

It is the same loop a designer runs with an engineer: a clear spec, a quick build, a close review, a shipped change. The difference is the round trip takes minutes, so the work gets tested on the real thing, not a mockup.
